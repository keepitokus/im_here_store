# «Я здесь» — магазин цифровых книг-подарков (MVP)

**Слоган:** «Истории, к которым возвращаются»  
**Язык интерфейса:** русский · **Валюта:** RUB (цены на сервере хранятся и вычисляются в копейках)

Production-ready MVP self-service магазина персональных цифровых книг-подарков. Покупатель без участия менеджера выбирает один из четырёх поводов, заполняет короткие карточки-вопросы, добавляет до 30 фотографий, смотрит предпросмотр с водяным знаком, оплачивает заказ и мгновенно получает приватную ссылку (`noindex` + опциональный PIN) и готовый QR-код.

## 1. Каталог и неизменные базовые цены

| SKU | Название | Первоначальная покупка | Продление | Палитра и состав |
|---|---|---:|---|---|
| `love-story` | «Наша история» | **4 990 ₽** (`499000` коп.) | Нет в MVP | Rose, кремовый/пыльно-розовый/бордо; знакомство, первое свидание, таймлайн 3–6 событий, фото, признание |
| `mother-thanks` | «Мама, спасибо» | **5 990 ₽** (`599000` коп.) | Нет в MVP | Тёплый кремовый/пастельно-синий; детское прозвище, воспоминания, чему научила, фото, письмо маме |
| `your-day` | «Твой день» | **5 990 ₽** (`599000` коп.) | Нет в MVP | Праздничный кремовый/золотой; именинник, поздравление, лучшие моменты, «За что мы тебя любим», фото |
| `first-year` | «Мой первый год» | **4 990 ₽** (`499000` коп.) | **990 ₽/год** (`99000` коп.) вручную | Молочный/пастельный шалфей; 0–12 месяцев, достижения, первые слова, фото, письмо малышу |

- У каждой книги **12 месяцев (365 дней)** размещения от подтверждения первого платежа.
- Для `first-year` по завершении оплаченного срока книга скрывается от внешних зрителей, данные сохраняются на **льготный период 90 дней** с уведомлениями за **30, 7 и 1 день**; доступно ручное продление на 365 дней за **990 ₽** разовым платежом (без автосписаний). Если текущий срок ещё активен — 365 дней прибавляются к текущей дате окончания, если истёк — к дате платежа продления.
- Для остальных трёх продуктов продление в MVP не продаётся; пользователю всегда доступен полный экспорт/скачивание архива своих материалов (`JSON + оптимизированные медиа`).

## 2. Локальный запуск

```bash
# 1. Установка зависимостей
npm install

# 2. (Опционально) Копирование переменных окружения
cp .env.example .env.local

# 3. Запуск автоматических тестов (Vitest)
npm test

# 4. Проверка линтера и production-сборки
npm run lint
npm run build

# 5. Запуск dev-сервера (порт 43123)
npm run dev
```

Приложение откроется по адресу `http://127.0.0.1:43123`.

## 3. Работа в режиме `DEMO_MODE` и тестовая оплата

Если боевые ключи `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` не заданы или `DEMO_MODE=true`:
1. В верхней части сайта отображается заметная плашка **`DEMO_MODE активен (локальная среда)`**.
2. При запуске автоматически создаются демонстрационные данные (`src/lib/demo-seed.ts`):
   - Покупатель: `demo@ya-zdes.ru` (с опубликованными книгами «Мой первый год» и «Наша история»).
   - Администратор: `admin@ya-zdes.ru` (доступ к `/admin`).
3. При запросе одноразового кода входа (OTP) в `DEMO_MODE` код выводится прямо на экран и автоматически подставляется в поле для мгновенного тестирования без внешнего SMTP-сервера.
4. На странице `/checkout/[bookId]` работает локальный симулятор платежей ЮKassa, позволяющий проверить:
   - Успешную оплату и мгновенную выдачу ссылки + QR-кода;
   - Сценарий задержки фоновой публикации («Платёж получен, готовим книгу») с кнопкой восстановления;
   - Сценарий неуспешной оплаты (`payment_failed`).
5. **Защита боевого домена:** симулятор платежей программно заблокирован (`isSimulatedPaymentAllowed()`), если `DEMO_MODE=false` или приложение запущено на боевом домене вне локальной среды.

## 4. Проверка Webhook ЮKassa

Эндпоинт вебхука: `POST /api/webhooks/yookassa`

Заголовок подписи: `x-yookassa-signature` (HMAC-SHA256 тела запроса с секретом `YOOKASSA_WEBHOOK_SECRET`).

Сервер проверяет:
- Подлинность подписи;
- Совпадение `providerPaymentId`, `orderId`, суммы в копейках (`amountKopecks`) и валюты (`RUB`);
- Идемпотентность: повторная доставка `payment.succeeded` для уже выполненного заказа (`fulfilled`) или существующей записи в `renewal_transactions` безопасно пропускается без удвоения срока размещения.

## 5. Боевые секреты и чеклист деплоя в Production

Перед запуском в production установите следующие переменные окружения:

| Переменная | Назначение |
|---|---|
| `DEMO_MODE=false` | Отключает демонстрационную плашку, вывод OTP-кодов в UI и платёжный симулятор |
| `NEXT_PUBLIC_DEMO_MODE=false` | Отключает клиентские подсказки демо-режима |
| `NEXT_PUBLIC_APP_URL` | Канонический HTTPS-домен магазина (например, `https://ya-zdes.ru`) |
| `SESSION_SECRET` | Криптостойкая строка не менее 32 байт для подписи сессий и хеширования PIN/OTP |
| `ADMIN_TOKEN` | Секретный токен для серверных вызовов `/api/admin/actions` |
| `DATABASE_URL` / `SQLITE_PATH` | Подключение к БД (PostgreSQL или постоянный том SQLite WAL) |
| `YOOKASSA_SHOP_ID` | Идентификатор магазина в ЮKassa |
| `YOOKASSA_SECRET_KEY` | Секретный ключ API ЮKassa |
| `YOOKASSA_WEBHOOK_SECRET` | Секрет для проверки вебхуков ЮKassa |
| `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Реквизиты объектного хранилища для медиафайлов |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM` | Реквизиты транзакционной почты |

### Ручные действия перед коммерческим запуском:
1. Заполнить юридические реквизиты продавца (ИП/ООО, ИНН, ОГРН) на страницах `/legal/offer`, `/legal/privacy`, `/legal/terms`.
2. Включить передачу данных для онлайн-чеков (54-ФЗ) в личном кабинете ЮKassa.
3. Настроить cron-задачу (раз в сутки), вызывающую `POST /api/admin/actions` с `{"action": "evaluate_entitlements"}` и заголовком `x-admin-token` для отправки предупреждений за 30, 7 и 1 день до истечения срока.
